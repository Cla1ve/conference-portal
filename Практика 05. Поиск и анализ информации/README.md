# Практика 5. Использование средств поиска и анализа информации

Справочник у меня офлайн: встроенная справка Python (`python -m pydoc`) и документация Flask, которая устанавливается вместе с пакетом (читаю её через `help()`).

## 1. Что искал

Хотел понять, что происходит, когда при записи в БД нарушается ограничение, и как правильно отвечать пользователю.
В справочнике `python -m pydoc sqlite3.IntegrityError` написано, что это ошибка, которая возникает при нарушении целостности (UNIQUE, внешние ключи, NOT NULL). Наследуется от `DatabaseError`, значит, её можно ловить отдельно, не трогая остальные ошибки БД. Скриншот: `01_офлайн_справочник_pydoc.png`.

Про обработчики ошибок во Flask читал `help(flask.Flask.errorhandler)`: можно зарегистрировать функцию на код ответа (404, 500) и вернуть свой ответ.

## 2. Ошибка

В регистрации я проверяю логин в `validate()`, а потом отдельно сохраняю. Если два человека одновременно регистрируются с одним логином, обе проверки проходят, а при `INSERT` вторая падает. Скрипт `tools/repro_race.py` воспроизводит такую ситуацию (подменяет `validate()` второго запроса).

Сообщение сервера:

```
sqlite3.IntegrityError: UNIQUE constraint failed: user.login
```

Расшифровка: в таблице `user` в колонке `login` уже есть такое значение, а на колонке стоит UNIQUE. По трассировке видно, что падает `self.db.execute` из `User.save()`, который вызывается в `routes/auth.py`. Пользователь при этом видел страницу «500 Internal Server Error». Скриншот: `02_ошибка_до_исправления.png`.

## 3. Исправление

- в `backend/routes/auth.py` вызов `user.save()` обернул в `try/except sqlite3.IntegrityError`, теперь возвращается 400 и понятное сообщение под полем логина;
- в `app.py` добавил обработчик 500: для API отдаёт JSON, для страниц шаблон `error.html`. Подробности остаются в логе.

После исправления тот же скрипт показывает статус 400 вместо 500. Скриншот: `03_после_исправления_и_коммит.png`.
