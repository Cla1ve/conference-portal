# Практика 3. Разработка модулей ИС в соответствии с ТЗ

## Структура проекта

```
conference-portal/
├── backend/        серверная часть (Flask, модели, валидаторы)
│   ├── models.py       классы User, Request, Review (наследуют BaseModel)
│   ├── validators.py   проверки полей
│   ├── security.py     хеширование, роли, CSRF
│   ├── db.py           класс Database (работа с SQLite)
│   └── routes/         маршруты: auth, requests, admin, pages
├── frontend/       шаблоны, стили и скрипты
│   ├── templates/
│   └── static/ (css, js, img, fonts)
├── database/       миграции и файл БД
│   └── migrations/
├── app.py          запуск приложения
└── init_db.py      создание базы
```

Фронтенд (HTML, CSS, JS) отделён от бэкенда: страницы отправляют данные на `/api/...` через `fetch`, сервер отвечает JSON.

## Что реализовано

1. **Регистрация.** Логин (уникальность проверяется по базе), пароль от 8 символов, ФИО, телефон и email по формату. Ошибки показываются под полями. На клиенте проверка в `auth.js`, на сервере те же правила в `validators.py`.
2. **Авторизация.** Вход по логину и паролю, при ошибке одинаковое сообщение «Неверный логин или пароль».
3. **Создание заявки.** Название, дата, время, помещение, оплата, описание.
4. **Просмотр заявок.** Участник видит только свои, у каждой статус.
5. **Панель администратора.** Все заявки карточками, кнопка смены статуса.
6. **ООП.** `BaseModel` с методами `validate()` и `save()`, от него наследуются `User`, `Request`, `Review`. Работа с БД спрятана в классе `Database`.
7. **Коммиты.** Работа разбита на коммиты, список в `git_log.png`.

## Как запустить

```
pip install -r requirements.txt
python init_db.py
python app.py
```

Сайт открывается на http://127.0.0.1:5000. Администратор из ТЗ: Conf2027 / Demo77.
