# Практика 9. Улучшение форм и интерфейса

## Что улучшено

1. **Валидация с выводом ошибок на странице.** Под каждым полем появляется красный текст, поле обводится красным. Раньше ошибка показывалась только после отправки, теперь ещё и сразу, когда человек вышел из поля (функция `liveValidate` в `common.js`). Когда поле исправлено, ошибка пропадает сама. Скриншоты: 01, 02.
2. **Выпадающие списки вместо текстовых полей.** «Помещение» и «Способ оплаты» выбираются из списков, значения берутся из таблиц `room` и `payment_method`. Сервер проверяет, что выбранный пункт есть в справочнике, поэтому подменить значение в запросе нельзя. Скриншот: 03.
3. **Фильтрация и карточки заявок у администратора.** Заявки показаны карточками. Фильтры: статус, помещение, дата и поиск по названию или ФИО (в поиске пауза 300 мс, чтобы не слать запрос на каждую букву). Фильтры работают вместе. Скриншоты: 04, 05, 06.
4. **Отзыв только после завершения мероприятия.** У заявки не в статусе «Завершено» вместо формы стоит подсказка. Это проверяется и на сервере: запрос на отзыв к незавершённой заявке отклоняется с сообщением «Отзыв можно оставить только после завершения мероприятия». Один отзыв на заявку. Скриншоты: 07, 08, 09.
5. **Коммиты.** Изменения закоммичены, см. историю git.

## Проверка

Правила отзывов и фильтров покрыты автотестами `tests/test_requests.py` (9 тестов: дата в прошлом, помещение не из списка, отзыв до завершения, отзыв дважды, чужая заявка, фильтры, переход статусов только вперёд). Запуск:

```
python -m unittest discover -s tests -t .
```

Все 18 тестов проекта проходят.
