# Требования к информационной системе «Конференции.РФ»

Практика 1. Выполнил Маматисаков Элмурат, 4ИСП9-45.

## 1. Предметная область

Организация, которая сдаёт помещения для мероприятий (конференции, встречи клубов, показы, мастер-классы). Сейчас заявки принимают по телефону и записывают в тетрадь, из-за этого путаются даты, и никто не знает, на каком этапе заявка.

Нужен сайт, где человек сам подаёт заявку на помещение, а администратор её обрабатывает. После мероприятия человек может оставить отзыв.

Помещения: аудитория, коворкинг, кинозал. Способы оплаты: при очном посещении и через СБП.

## 2. Назначение системы

- принимать заявки на проведение мероприятий через сайт;
- показывать человеку, на каком этапе его заявка;
- дать администратору один список всех заявок с фильтрами и сменой статуса;
- собирать отзывы о прошедших мероприятиях.

## 3. Пользователи и роли

| Роль | Кто это | Что может |
|------|---------|-----------|
| Гость | Любой посетитель без входа | Смотреть главную страницу и ближайшие мероприятия, зарегистрироваться, войти |
| Участник | Зарегистрированный пользователь | Всё, что гость, плюс: создавать заявки, видеть только свои заявки, оставлять отзыв после завершения |
| Администратор | Сотрудник организации | Видеть все заявки, фильтровать их, менять статус |

Администратор создаётся заранее (логин Conf2027), через регистрацию его создать нельзя.

## 4. Функциональные требования

### Гость
1. Просмотр главной страницы со списком подтверждённых мероприятий.
2. Регистрация: логин, пароль, ФИО, телефон, email.
3. Вход по логину и паролю.

### Участник
1. Авторизация и выход.
2. Создание заявки: название, дата, время, помещение (список), способ оплаты (список), описание.
3. Просмотр только своих заявок со статусом.
4. Отзыв (текст и оценка 1-5) только после того, как заявка получила статус «Завершено». Один отзыв на заявку.
5. Отмена своей заявки, пока она «Новая».

### Администратор
1. Просмотр всех заявок карточками.
2. Фильтры: статус, помещение, дата, поиск по названию или ФИО.
3. Смена статуса строго по порядку: Новая → Мероприятие назначено → Завершено.
4. Просмотр отзывов к заявкам.

### Статусы заявки
| Номер | Название |
|-------|----------|
| 1 | Новая |
| 2 | Мероприятие назначено |
| 3 | Завершено |

## 5. Правила проверки данных

| Поле | Правило |
|------|---------|
| Логин | 6-30 символов, латиница, цифры, _; уникальный |
| Пароль | не короче 8 символов |
| ФИО | 2-3 слова кириллицей |
| Телефон | формат 8(900)-123-45-67 |
| Email | корректный адрес, уникальный |
| Название мероприятия | 3-200 символов |
| Дата | не раньше сегодняшней |
| Время | ЧЧ:ММ |
| Оценка | число от 1 до 5 |

## 6. Нефункциональные требования

- **Адаптивность.** Сайт должен нормально работать на компьютере и на телефоне (экран 390×844).
- **Безопасность.** Пароли хранятся только в виде хеша. Запросы к БД с параметрами. Участник не видит чужие заявки, администраторская часть закрыта для остальных. Сессия сбрасывается через 30 минут без действий.
- **Производительность.** Страница должна открываться быстро, список заявок загружается меньше чем за секунду при нескольких сотнях записей.
- **Удобство.** Ошибки показываются рядом с полем, а не только в сообщении сверху. Выбор помещения и оплаты через выпадающие списки.
- **Совместимость.** Chrome, Edge, Яндекс Браузер последних версий.

## 7. Технологии

Python, Flask, SQLite, HTML, CSS, JavaScript без фреймворков. Git для версий.

## 8. Что не входит в проект

Онлайн-оплата, письма на почту, личные сообщения. Оплата только отмечается способом.
